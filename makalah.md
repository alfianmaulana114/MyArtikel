## BAB I — PENDAHULUAN

### 1.1 Latar Belakang Masalah

**Isi dengan konteks berikut:**

Dalam dunia akademik dan penelitian, mahasiswa, dosen, dan peneliti menghadapi tantangan besar dalam mengelola referensi, jurnal, dan artikel ilmiah. Jumlah literatur yang harus dikaji terus meningkat, namun alat yang tersedia sering kali tidak memadai. Beberapa masalah utama yang dihadapi adalah:

- **Referensi tersebar dan tidak permanen** — Bookmark browser sering rusak atau link jurnal menjadi mati, sehingga referensi penting hilang.
- **Proses membaca yang tidak efisien** — Konten web penuh dengan iklan, pop-up, dan distraksi visual yang mengurangi fokus saat membaca paper atau artikel ilmiah.
- **Kesulitan menyusun rangkuman literatur** — Membaca puluhan hingga ratusan artikel panjang memakan waktu luar biasa, sementara deadline penelitian mendesak.
- **Catatan dan insight tidak terorganisir** — Catatan tentang artikel sering tersimpan di berbagai tempat (notebook, Word, sticky notes) sehingga sulit ditemukan kembali saat menyusun laporan.
- **Manajemen bibliografi manual** — Menyusun daftar pustaka dan format kutipan (APA, MLA, Chicago) secara manual rentan salah dan memakan waktu.
- **Tidak ada workspace riset terintegrasi** — Tidak ada tempat untuk menggabungkan artikel, catatan, outline, dan bibliografi dalam satu project penelitian.
- **Data riset tidak sinkron antar perangkat** — Peneliti sering bekerja di laptop, tablet, dan ponsel, namun data tidak terintegrasi.

Oleh karena itu, dibutuhkan sebuah sistem informasi berbasis web yang secara khusus dirancang untuk **mendukung proses pengerjaan penelitian** — mulai dari pengumpulan referensi, pembacaan efisien, perangkuman otomatis, pengelolaan catatan, penyusunan bibliografi, hingga sinkronisasi data riset antar perangkat. **MyArtikel** hadir sebagai solusi komprehensif untuk permasalahan tersebut.

### 1.2 Tujuan Proyek

**Tujuan umum:**
Membangun sistem informasi berbasis web bernama **MyArtikel** yang berfungsi sebagai **pendukung proses penelitian**, memungkinkan pengguna untuk mengumpulkan referensi, membaca jurnal/artikel secara efisien, merangkum literatur dengan AI, mengelola catatan penelitian, menyusun bibliografi otomatis, dan menyinkronkan data riset antar perangkat.

**Tujuan khusus (jabarkan):**
1. Menyediakan fitur penyimpanan referensi via URL atau unggahan PDF dengan ekstraksi konten otomatis ke dalam library pribadi.
2. Menyajikan tampilan bacaan bersih (clean reader) yang nyaman dan bebas distraksi untuk fokus membaca jurnal/artikel.
3. Mengimplementasikan sistem pengelompokan referensi dengan tag warna, bookmark kategori, dan folder riset (project).
4. Mengintegrasikan AI summarization (Google Gemini API) dengan fallback lokal (TF-IDF) untuk mempercepat review literatur.
5. Menyediakan rich text notes dengan paragraph anchoring agar peneliti dapat mencatat insight spesifik pada bagian tertentu artikel.
6. Menyediakan workspace riset (project) dengan outline, bibliografi otomatis, dan citation chat (RAG) untuk berdiskusi dengan AI tentang kutipan.
7. Menyediakan fitur ekspor PDF multi-template (Akademik, Majalah, Minimal, Bisnis, Default) untuk keperluan laporan dan presentasi.
8. Mengembangkan sistem pencarian full-text dengan filter lanjutan dan analitik untuk menemukan kembali referensi dengan cepat.
9. Mengembangkan sistem sinkronisasi data riset antar perangkat secara real-time menggunakan WebSocket.
10. Membangun antarmuka admin untuk monitoring sistem dan manajemen pengguna.

### 1.3 Ruang Lingkup Proyek

**Batasan proyek:**

| Aspek | Ruang Lingkup |
|-------|--------------|
| **Platform** | Web application (responsive, tidak ada aplikasi mobile native) |
| **Pengguna** | Mahasiswa, dosen peneliti, content writer akademik, dan admin |
| **Fitur Utama** | Save referensi (URL/PDF), clean reader, tags, bookmarks, rich text notes, AI summary, project workspace (outline + bibliography + citation chat), knowledge graph, PDF export, search, cross-device sync |
| **Teknologi** | Laravel 13 (backend), Alpine.js + Tailwind CSS (frontend), MySQL (database utama), Node.js Express (sync service), PostgreSQL (sync DB) |
| **AI Provider** | Google Gemini API (primary), TF-IDF lokal (fallback) |
| **PDF Parsing** | smalot/pdfparser |
| **Queue** | Database driver dengan 5 level prioritas |
| **Batasan** | Tidak menyediakan aplikasi mobile native; tidak mendukung video; maksimal 5 perangkat per pengguna untuk sync; tidak mendukung login ke situs sumber untuk bypass paywall |

### 1.4 Manfaat Proyek

**Manfaat bagi peneliti/mahasiswa:**
1. **Pengumpulan Referensi Terpusat** — Semua jurnal, paper, dan artikel referensi tersimpan permanen dalam satu library pribadi yang aman.
2. **Efisiensi Review Literatur** — AI summarization memungkinkan peneliti memperoleh poin-poin utama dari artikel panjang dalam hitungan detik, mempercepat proses literature review.
3. **Pembacaan Fokus** — Clean reader menghilangkan iklan dan distraksi, meningkatkan konsentrasi saat membaca paper akademik.
4. **Organisasi Catatan Penelitian** — Notes dengan paragraph anchoring memungkinkan pencatatan insight tepat pada bagian artikel yang relevan.
5. **Workspace Riset Terstruktur** — Project workspace menggabungkan artikel, outline, dan bibliografi dalam satu tempat, memudahkan penyusunan proposal, skripsi, atau paper.
6. **Bibliografi Otomatis** — Sistem menghasilkan daftar pustaka otomatis dari artikel yang terhubung ke project, mengurangi kesalahan manual.
7. **Citation Chat (RAG)** — Peneliti dapat berdiskusi dengan AI mengenai kutipan dari koleksi artikel mereka dalam format APA/MLA/Chicago.
8. **Akses Lintas Perangkat** — Sinkronisasi memungkinkan peneliti mengakses data riset dari laptop, tablet, maupun ponsel kapan saja.
9. **Ekspor Akademik** — PDF export dengan template akademik memudahkan penyusunan laporan dan presentasi.

**Manfaat akademik:**
- Menerapkan konsep sistem informasi, arsitektur monolith dengan supporting microservice, queue processing, AI integration, dan real-time sync dalam satu proyek nyata yang relevan dengan kebutuhan penelitian.
- Mempraktikkan manajemen proyek tim dan kolaborasi pengembangan perangkat lunak.

## BAB II — ANALISIS KEBUTUHAN

### 2.1 Analisis Kebutuhan Fungsional dan Non-Fungsional

#### A. Kebutuhan Fungsional (Functional Requirements)

**Modul Autentikasi & Manajemen Pengguna**

- RF-02: Pengguna dapat login, logout, reset password, dan verifikasi email.

- RF-06: Sistem mengekstrak konten referensi secara otomatis menggunakan background job (queue `low-priority`).
- RF-07: Pengguna dapat melihat referensi dalam tampilan bersih (clean reader) tanpa iklan dan script berbahaya.
- RF-08: Sistem melacak status pemrosesan referensi (queued → fetching → extracting → ready/failed).
- RF-09: Pengguna dapat generate kutipan (citation) dari metadata artikel dan meminta paraphrase kutipan via AI.

**Modul Organisasi Referensi**
- RF-10: Pengguna dapat membuat tag dengan warna dan menautkannya ke referensi (bulk tagging supported, autocomplete, auto-suggest).
- RF-11: Pengguna dapat membuat bookmark dengan kategori warna, favorit, arsip, pengingat (reminder), dan status baca (read/unread).
- RF-12: Pengguna dapat membuat catatan (notes) per referensi dengan rich text editor (Quill.js) dan paragraph anchoring (terikat ke paragraf spesifik).

**Modul AI Summarization (Review Literatur)**
- RF-14: Pengguna dapat meminta ringkasan artikel/jurnal dengan satu klik (on-demand).
- RF-15: Sistem menggunakan Google Gemini API sebagai summarizer utama (abstractive summary).
- RF-16: Jika kuota Gemini habis atau error, sistem otomatis beralih ke summarizer lokal TF-IDF (extractive summary).
- RF-17: Ringkasan dicache selama 24 jam berdasarkan hash konten untuk menghindari pemrosesan berulang.
- RF-18: Sistem membatasi penggunaan: 100 request/hari untuk Gemini, 1000 request/hari untuk lokal.
- RF-19: Pengguna dapat meregenerate ringkasan jika hasil tidak memuaskan.
- RF-20: Sistem mendukung bulk summarization untuk multiple artikel sekaligus via API.

**Modul PDF Export (Output Akademik)**

- RF-22: Sistem menyediakan 5 template PDF: Default, Academic, Magazine, Minimal, Business.
- RF-23: Pengguna dapat mengatur opsi ekspor: format kertas (A4, A3, Letter, Legal), orientasi, ukuran font, nomor halaman, watermark, include metadata/summary/TOC/images.
- RF-24: Proses ekspor besar dijalankan di background queue `exports` dengan tracking status.
- RF-25: File PDF memiliki masa kadaluarsa 30 hari dan dihapus otomatis.
- RF-26: Pengguna dapat melihat riwayat ekspor, mendownload, preview, dan menghapus file ekspor.

- RF-28: Sistem menghasilkan bibliografi otomatis dari referensi yang terhubung ke project.
- RF-29: Pengguna dapat menambah dan menghapus referensi dari project.
- RF-30: Pengguna dapat menduplikat project beserta isinya.
- RF-31: Pengguna dapat membuat outline bersarang (section-based, nested, drag-drop ordering) untuk struktur penelitian.

## BAB III — PEMBAHASAN PROYEK AKHIR

### 3.1 Deskripsi Proyek Akhir

**MyArtikel** adalah sistem informasi berbasis web yang secara khusus dirancang sebagai **pendukung proses pengerjaan penelitian**. Sistem ini membantu mahasiswa, dosen, dan peneliti dalam mengelola seluruh siklus riset awal — mulai dari pengumpulan referensi, review literatur, pencatatan insight, penyusunan outline, hingga generate bibliografi dan kutipan.

Sistem dibangun dengan arsitektur **Laravel 13 monolith** sebagai aplikasi utama, didukung oleh **Node.js Express service** untuk sinkronisasi lintas perangkat, dan **TypeScript package** untuk ekstraksi dan sanitasi konten referensi.

**Cara Kerja Sistem (High-Level) untuk Penelitian:**
1. Pengguna mendaftar/login melalui Laravel Breeze authentication.
2. Pengguna submit URL jurnal/paper atau upload PDF hasil scan/download.
3. Background job (`low-priority` queue) mengekstrak konten menggunakan `article-ingestion` package (Cheerio + DOMPurify + JSDOM).
4. Konten disimpan di MySQL dengan status `ready`; metadata (domain, judul, hash) tersimpan.
5. Pengguna membaca referensi di Clean Reader, menambah tag (misal: "Machine Learning", "2024"), bookmark, dan rich text notes dengan paragraph anchoring.
6. Saat pengguna klik "Generate Summary", job dimasukkan ke `summarization` queue.
7. `SummarizationService` memutuskan: gunakan Gemini API (jika kuota tersedia) atau TF-IDF lokal.
8. Ringkasan disimpan di tabel `summaries` dengan cache 24 jam — mempercepat literature review.
9. Pengguna dapat membuat `project` (misal: "Skripsi: Analisis Sentimen"), menambah referensi ke project, membuat outline bab, dan menggunakan citation chat (RAG) untuk bertanya ke AI tentang kutipan dalam format APA/MLA/Chicago.
10. Pengguna dapat mengekspor referensi ke PDF melalui `exports` queue menggunakan `AdvancedPdfExportService` — cocok untuk lampiran laporan.
11. Perubahan data disinkronkan ke perangkat lain melalui Node.js sync service (WebSocket + PostgreSQL).
12. Admin mengelola sistem melalui dashboard admin.

### 3.2 Tujuan Spesifik Proyek

| No | Tujuan Spesifik | Indikator Keberhasilan |
|----|-----------------|------------------------|

### 5.2 Kendala yang Dihadapi dan Solusinya

| No | Kendala | Dampak | Solusi |
|----|---------|--------|--------|
| **K1** | **Ekstraksi konten dari berbagai struktur HTML** — Setiap jurnal/website memiliki struktur DOM yang berbeda, menyebabkan hasil ekstraksi tidak konsisten. | Referensi terkadang tidak lengkap atau salah parsing. | Menggunakan `article-ingestion` package dengan Cheerio + heuristic logic untuk mendeteksi container konten utama. Fallback ke meta tags jika parsing gagal. |
| **K2** | **Rate limiting dan quota Google Gemini API** — API memiliki batasan request per hari. | Sering terjadi error 429 saat banyak pengguna generate summary bersamaan. | Mengimplementasikan `QuotaManagementService` yang melacak penggunaan harian per user. Jika quota tercapai, sistem otomatis beralih ke `LocalSummarizationService` (TF-IDF). |
| **K3** | **Timeout saat batch export PDF besar** — Export 200 referensi sekaligus menyebabkan request timeout dan memory exhaustion. | Proses gagal di tengah jalan; user tidak mendapat file. | Mengubah export besar menjadi background job yang diproses di `exports` queue. User hanya menerima notifikasi/download link setelah job selesai. Batch sync dibatasi 50; batch async dibatasi 200. |
| **K4** | **Konflik sinkronisasi antar perangkat** — User mengedit catatan di perangkat A dan B secara bersamaan tanpa internet, lalu sync saat online. | Data tertimpa atau duplikat. | Mengimplementasikan 4 strategi resolusi konflik: Last Write Wins, Manual Merge, Server Wins, Client Wins. User dapat memilih strategi default di pengaturan. |
| **K5** | **SSRF vulnerability saat fetch URL** — User bisa memasukkan URL internal network (localhost, private IP) yang membahayakan server. | Server bisa digunakan untuk scan port internal atau akses service lokal. | Mengimplementasikan `SsrfProtectionService` yang memvalidasi URL sebelum fetch — memblokir private IP ranges, localhost, dan URL scheme yang tidak diizinkan. |
| **K6** | **Kompleksitas state management di frontend** — Alpine.js tidak memiliki state management bawaan seperti Vuex, menyebabkan data antar komponen sulit diatur. | Kode JavaScript menjadi berantakan dan sulit debug. | Menggunakan `x-data` yang terstruktur dengan baik, memanfaatkan `localStorage` untuk state persisten (theme), dan menggunakan Laravel Blade components untuk encapsulation. |
| **K7** | **Perbedaan environment development tim** — Anggota tim menggunakan OS dan PHP version yang berbeda, menyebabkan masalah dependency. | `composer install` gagal atau fitur tidak berjalan konsisten. | Menggunakan Laragon sebagai environment standar, menyertakan `composer.json` dan `package.json` yang lock version, dan mendokumentasikan setup di `AGENTS.md`. |

### 8.2 Strategi Manajemen Proyek

Proyek MyArtikel dikelola dengan metodologi **Agile Kanban** yang disederhanakan untuk skala tim kecil (3 orang):

#### A. Struktur Sprint
- **Durasi Sprint:** 1 minggu (selama 15 minggu perkuliahan).
- **Sprint Planning:** Setiap awal minggu (Senin) — menentukan task prioritas minggu itu.
- **Daily Standup:** Setiap hari kuliah (15 menit) — laporan progress, blocker, dan rencana hari ini.
- **Sprint Review:** Akhir minggu (Jumat) — demo fitur yang selesai ke seluruh tim.
- **Retrospective:** Setiap 2 minggu — evaluasi apa yang berjalan baik, buruk, dan perbaikan proses.

#### B. Priorisasi Task
Task diprioritaskan dengan framework **MoSCoW**:
- **Must Have:** Autentikasi, save referensi, clean reader, tags, bookmarks, AI summary, PDF export, project workspace, sync. *(Dikerjakan di minggu 1–12)*
- **Should Have:** Advanced search analytics, citation chat RAG, knowledge graph, bookmark analytics. *(Dikerjakan di minggu 10–14)*
- **Could Have:** Browser extension, mobile app, email digest, OCR. *(Ditunda ke pengembangan lanjutan)*
- **Won't Have (this version):** Collaborative project multi-user, public API. *(Ditunda ke versi 2.0)*

#### C. Communication Tools
- **GitHub Repository:** Source code management, pull request, code review.
- **WhatsApp Group:** Komunikasi harian, sharing resource, dan reporting blocker.
- **Google Docs/Drive:** Dokumentasi bersama, PRD, dan laporan progres.
- **Laragon:** Shared local environment untuk menghindari "works on my machine".

#### D. Version Control Strategy
- **Branching:** `main` (stable), `develop` (integration), `feature/nama-fitur` (development per fitur).
- **Commit Message:** Menggunakan format conventional commits (`feat:`, `fix:`, `docs:`, `test:`).
- **Pull Request:** Setiap fitur baru wajib PR ke `develop` dengan code review minimal 1 anggota lain.
- **Merge:** Merge ke `main` hanya dilakukan setelah sprint review dan semua tests passing.

### 8.3 Evaluasi Kolaborasi Tim

#### A. Keberhasilan Kolaborasi

| Aspek | Evaluasi |
|-------|----------|
| **Komunikasi** | Standup harian berjalan efektif; blocker diselesaikan dalam 1–2 hari. |
| **Pembagian Tugas** | Tugas didistribusikan berdasarkan keahlian masing-masing; tidak ada anggota yang overload. |
| **Code Review** | PR review dilakukan konsisten; bug ditemukan lebih awal sebelum merge ke develop. |
| **Dokumentasi** | Dokumentasi teknis ditulis paralel dengan coding; tidak ada technical debt dokumentasi. |
| **Conflict Resolution** | Konflik merge minimal karena pembagian modul yang jelas. |

#### B. Tantangan Kolaborasi

| Tantangan | Dampak | Solusi yang Diterapkan |
|-----------|--------|------------------------|
| Perbedaan jadwal kuliah anggota | Sulit menyatukan waktu standup | Standup dilakukan via chat jika tidak bisa offline; demo di hari Jumat wajib hadir. |
| Perbedaan tingkat keahlian teknis | Beban kerja tidak merata di awal | Pair programming untuk fitur kompleks (summarization, sync, RAG); knowledge sharing session setiap minggu. |
| Scope creep — ide fitur baru muncul terus | Waktu development terbatas | Menggunakan MoSCoW prioritas; fitur baru dimasukkan ke backlog pengembangan lanjutan. |

#### C. Lesson Learned

1. **Pentingnya Dokumentasi Awal** — PRD dan database design yang jelas di minggu pertama menghemat waktu debugging di minggu-minggu berikutnya.
2. **Queue System adalah Lifesaver** — Menggunakan queue untuk extraction, summarization, dan export mencegah timeout dan membuat sistem lebih scalable.
3. **Testing Sejak Awal** — Menulis tests paralel dengan development mengurangi bug yang ditemukan saat integrasi.
4. **UI Consistency** — Menggunakan Tailwind CSS design system sejak awal memastikan UI konsisten di seluruh halaman.
5. **Service Layer Pattern** — Memisahkan business logic ke Services (bukan hanya Controller) membuat kode lebih mudah di-test dan di-maintain.
6. **Communication > Perfection** — Lebih baik melaporkan blocker cepat daripada menyembunyikannya dan memperlambat sprint.

## BAB IX — PENUTUP

### 9.1 Kesimpulan Proyek

Berdasarkan hasil analisis, perancangan, pengembangan, pengujian, dan evaluasi yang telah dilakukan, dapat disimpulkan bahwa:

1. **MyArtikel berhasil dibangun** sebagai sistem informasi berbasis web yang berfungsi sebagai **pendukung proses pengerjaan penelitian**, menggunakan Laravel 13 sebagai backend monolith, Alpine.js + Tailwind CSS sebagai frontend, serta Node.js Express sebagai supporting microservice untuk sinkronisasi.

2. **Seluruh fitur utama telah diimplementasikan dan diuji** dengan baik, meliputi: penyimpanan referensi via URL/PDF, clean reader, tag & bookmark management dengan analytics, rich text notes dengan paragraph anchoring, AI summarization (Gemini + TF-IDF fallback) dengan bulk generation, multi-template PDF export dengan background processing, project workspace dengan bibliography dan citation chat (RAG), knowledge graph, full-text search dengan analytics, serta cross-device sync real-time dengan conflict resolution.

3. **Arsitektur queue-based dan modular** yang digunakan terbukti efektif dalam menangani proses berat (ekstraksi referensi, generate summary, batch export) tanpa mengganggu responsivitas UI.

4. **Sistem lolos pengujian komprehensif** meliputi unit testing (PHPUnit & Jest), feature testing (8 test suites), manual UAT (20+ skenario), security testing (5 aspek), dan performance testing (8 metrik) dengan hasil memuaskan.

5. **Dokumentasi teknis yang lengkap** (13 file Markdown) memudahkan pemeliharaan dan pengembangan lanjutan oleh tim maupun pihak lain di masa depan.

6. **Pengalaman pengguna (UX)** menjadi prioritas utama melalui desain earth-tone minimal distraksi, dark mode, responsive layout, dan inline guidance — yang semuanya selaras dengan visi MyArtikel sebagai "cozy research companion" yang mendukung produktivitas penelitian.

### 9.2 Saran untuk Pengembangan Proyek di Masa Depan

Agar MyArtikel dapat berkembang lebih jauh dan memberikan nilai tambah yang lebih besar bagi peneliti, berikut adalah saran-saran yang direkomendasikan:

1. **Pengembangan Browser Extension** — Prioritas tertinggi. Extension Chrome/Firefox yang terintegrasi dengan Google Scholar, ResearchGate, dan Mendeley akan secara signifikan meningkatkan adoption karena mengurangi friction saat menyimpan referensi.

2. **Aplikasi Mobile Native** — Membuka pasar pengguna mobile yang lebih besar dan memberikan pengalaman membaca PDF jurnal secara offline melalui local database.

3. **Penambahan OCR untuk PDF Scan** — Banyak jurnal lama dan paper conference tersedia dalam bentuk scan gambar. Integrasi Tesseract OCR akan memperluas kemampuan sistem dalam menangani dokumen tersebut.

4. **Kolaborasi Multi-User dalam Project** — Memungkinkan tim riset (misalnya: kelompok tugas akhir atau lab penelitian) untuk berbagi project, outline, dan catatan secara real-time — mirip Google Docs untuk riset.

5. **Integrasi Reference Manager** — Export bibliografi tidak hanya ke PDF tetapi juga ke format reference manager populer (Zotero, Mendeley, EndNote) untuk memudahkan penelitian akademik lintas platform.

6. **Peningkatan AI dengan Fine-tuning** — Mengumpulkan data ringkasan dan citation yang dihasilkan user untuk fine-tune model lokal (misalnya menggunakan BERT/IndoBERT) agar kualitas local fallback mendekati Gemini dan lebih relevan dengan domain akademik Indonesia.

7. **Monetisasi via Freemium Model** — Menawarkan tier gratis dengan limitasi (kuota summarization, jumlah project) dan tier berbayar untuk unlimited access — menjadikan MyArtikel potensial startup di bidang edutech/researchtech.

8. **Community Features** — Menambahkan fitur sharing referensi publik, following peneliti lain, dan rekomendasi artikel berdasarkan interest — membangun komunitas peneliti.
